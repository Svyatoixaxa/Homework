## 1. Постановка задачи

**Бизнес-задача:** помочь специалисту по информационной безопасности быстрее находить потенциально подозрительные события авторизации, чтобы сократить объём ручной проверки журналов.

**ML-задача:** бинарная классификация событий авторизации:
- `0` — обычная попытка входа;
- `1` — потенциально подозрительная попытка входа.

Это **учебная постановка задачи**. На этапе задания 1 модель не обучается — выполняются выбор метрики и разведочный анализ данных (EDA).

## 2. Набор данных

Файл `auth_events.csv` содержит **2 400 синтетических** записей, созданных скриптом `generate_data.py` на Python (`NumPy`, `pandas`) с фиксированным зерном случайных чисел (`seed=42`). **Это не выгрузка с реального сервера.** Метки подозрительных событий также заданы генератором вероятностно; они не подтверждены реальными расследованиями инцидентов.

Признаки:

| Поле | Описание |
| --- | --- |
| `event_id` | Идентификатор события |
| `hour` | Час входа (0–23) |
| `failed_attempts_24h` | Количество неудачных попыток за 24 часа |
| `new_device` | Новое устройство: 1 — да, 0 — нет |
| `unusual_country` | Необычная страна входа: 1 — да, 0 — нет; возможны пропуски |
| `vpn_used` | Использование VPN: 1 — да, 0 — нет |
| `is_suspicious` | Целевая метка: 1 — подозрительно, 0 — обычно |

## 3. Метрика качества

**Основная метрика — F2-score.** Она придаёт полноте (`Recall`) больший вес, чем точности (`Precision`): в задачах ИБ пропустить потенциально опасный вход обычно хуже, чем направить лишнее событие на проверку. Дополнительно следует контролировать `Precision` и число ложных срабатываний, чтобы не перегружать аналитика.

На данном этапе значение F2-score не вычисляется, поскольку модель ещё не обучена.

## 4. EDA: что сделано

Разведочный анализ находится в файле `Задание_1_EDA_Авторизации.ipynb`. Использованы `pandas`, `matplotlib`, `seaborn`:

1. Размер набора, типы данных, описательная статистика, пропуски, проверка повторных `event_id`.
2. Распределение обычных и подозрительных входов.
3. Количество неудачных попыток по классам.
4. Доля подозрительных событий в разные часы.
5. Сравнение новых устройств и необычных стран входа.
6. Матрица корреляций признаков.

**Результаты проверки:** 2 204 обычных события и 196 подозрительных; в `unusual_country` — 37 пропущенных значений.

**Вывод:** классы несбалансированы; перед будущим обучением нужно обработать пропуски, корректно разделить данные на обучающую и тестовую выборки и учитывать дисбаланс. Связи признаков с меткой на синтетическом наборе ожидаемы, поскольку сам генератор использует эти признаки для формирования метки.

## 5. Как запустить

1. Установить Python и Jupyter Notebook (или открыть файл `.ipynb` через VS Code с расширением Jupyter).
2. В папке репозитория установить зависимости:

   ```bash
   pip install -r requirements.txt
   ```

3. При необходимости заново создать набор данных:

   ```bash
   python generate_data.py
   ```

4. Открыть `Задание_1_EDA_Авторизации.ipynb` и выполнить все ячейки (`Run All`). CSV должен находиться рядом с ноутбуком.

## 6. Ограничения

Данные синтетические, поэтому статистические закономерности в них отражают сценарий генерации, а не реальную частоту атак. Для проверки применимости будущей модели потребуются обезличенные реальные журналы с проверенной разметкой.
